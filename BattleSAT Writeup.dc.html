Playing Battleship in an imperfect world

What happens when an automated system misinterprets its own feedback loop? Here I explore the use of SAT solvers to recover ground truth from experimental uncertainty.  

z3 / maxsat python streamlit constraint solving robotics
Simulation of automated Battleship played on a standard 96-well plate with pH-sensitive reagents. Features configurable parameters for optical noise and sampling error rates to test model robustness. Run shown: 10% error rate, 50% RGB signal noise
01 — the problem

Seeing the closed-loop system run autonomously on the OT-2 for the first time was exciting, until an RGB sampling error misclassified a water position as a hit. I could only watch as the rest of the run devolved into tragic futility, the simple error compounding across remaining steps.

At around the same time, I was exploring the use of SAT solvers for sequence design. It occurred to me that as humans, we naturally infer that an isolated "hit" completely surrounded by water is probably a misclassification. What if we could use logical constraints derived from the rules of battleship to detect these discrepancies and dynamically correct the belief map?

02 — the setup

In a previous project, I worked with a team to play battleship autonomously on a liquid handler. In both that project and this simulation, we treat a 96-well plate as a battleship board, where each query returns an RGB reading. A confidence classifier converts this optical signal into a hit or miss verdict. But the original version only included either hits or misses and treated the results as reliable, while this one does not take for granted the reliability. 

To stress-test how SAT solvers degrade under realistic conditions, we introduce two configurable error sources: oracle errors (contaminated wells reporting wrong results at 0–20% rates) and sensor noise (Gaussian noise on RGB channels from 0–60 std dev), which affects the confidence scores the classifier receives. Instead of maintaining a Bayesian belief map, we employ a simple Hunt-Target heuristic which displayed a similar performance in another project simulation. 

03 — detecting and correcting errors

We implemented two validation modes. SAT mode runs reactively: after accumulating observations, it checks whether the board satisfies battleship constraints. If an UNSAT condition surfaces, such as a lone hit surrounded by water, or overlapping ships, the solver repairs the board by flipping the conflicting bits. It's fast but can miss errors that don't trigger a hard contradiction.

Dynamic mode takes a more aggressive approach, maintaining a persistent MaxSAT solver that refines a best-guess board after every single query. We catch errors faster, but computation time is extremely slow - often intractable.

06 - let's play!

A Streamlit app wraps the simulation, letting you configure oracle error rates, noise levels, move strategies, and validation modes, then watch the algorithm play in real-time. As each query executes, you see the board state update, the solver's repair log unfold, and the belief map converge. You can pause, inspect why a particular choice was made, and understand exactly when and why the model recovers from errors.

In the images above, we see that by some intermediate step in the simulation, Wells F4, H5, and H9 are misidentified as hits, and E10 is misidentified as a miss. At a later step, the MaxSAT audit is triggered and the board is recovered to almost ground truth, with the exception of E10. 

05 — it's not that easy

The two images below show the end state of the simulation. The left picture shows the color of each well as determined by the camera and computer vision model, accompanied by an uncertainty value ranging from 0 to 1. The image on the right shows the model's current belief of the board state. Even though earlier we saw multiple errors, by the end of the simulation we were able to recover the ground truth. 

For reasonably small error rates, we're able to recover the board as shown above. But at higher error rates, MaxSAT literally grinds to a halt as it is unable to find a satisfactory board combination. The good news is that the dynamic solver shows measurable promise. Where naive board tracking plateaus early under contamination, continuous MaxSAT refinement extends the accuracy plateau and enables recovery from mid-game errors. This gives us a real-world-applicable testbed for understanding how SAT solvers behave when the problem itself is uncertain.
