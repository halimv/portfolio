A fully closed-loop, automated game of Battleship

How can we give a robot everything it needs to play Battleship with itself? And why would we want to? 

In collaboration with Ashwath Raghuram, Baiding Chen, Jeffrey Yang

python opentrons http closed-loop systems
In the middle of the game, an OT-2 dispenses cabbage juice into a selected well. In the following steps, a camera will take a picture after waiting for a color change to occur. The picture is sent to a computer which samples pixels from the selected well to determine whether the position is a hit/miss and chooses the next step based on the outcome of the previous step.
01 - closing the loop

Automating modern science requires moving beyond simple mechanical execution. Transferring a manual assay onto a liquid handler speeds up pipetting, but it leaves the core bottleneck intact. To truly advance scientific discovery, we must design systems that close the loop between the conclusion of one experiment and the initiation of the next.

Traditionally, a human scientist analyzes data, forms a new hypothesis, and designs the subsequent experiment to test it. True laboratory automation requires embedding that iterative reasoning directly into the system, enabling machines to continuously analyze outcomes and autonomously drive the next step of an investigation.

02 - what does it have to do with biology?

While Battleship serves as a simplified proof of concept, this closed-loop architecture demonstrates how similar frameworks could potentially transform real-world biological workflows. Rather than target coordinates on a game board, future iterations of this system could evaluate chemical analogs in active-learning drug screens, using live optical readouts to dynamically select and dilute promising compounds instead of running static, multi-thousand-compound libraries. The same iterative logic could theoretically be applied to directed evolution or adaptive media optimization, where an algorithm acts on live pH shifts or cell density measurements to selectively propagate high-performing protein variants or adjust feeding schedules on the fly. By using the game as a functional proxy, the framework illustrates how AI-driven decision engines might one day autonomously steer high-throughput biological experimentation to shorten cycle times and conserve expensive reagents.

03 - art imitates life

Evaluating closed-loop frameworks requires a controlled, reproducible testing ground, and the game Battleship provides an ideal proxy for the scientific method. The gameplay directly mirrors the research process: formulating a hypothesis (selecting a target coordinate), running an experiment (taking a shot), analyzing the outcome (observing a hit or miss), and designing the next test based on previous data.

By adapting the standard game board to a 96-well plate format, the setup translates game mechanics into chemical and optical signals. Using pH-sensitive reagents, board state changes can be captured by a camera, converted into usable data, and fed into an algorithmic decision loop.

04 — the closed-loop system architecture

Standard industry liquid handlers are often proprietary and difficult to integrate with external software. The affordable Opentrons OT-2 provides a flexible platform for testing custom, programmatic control.

The system relies on chemical indicators, computer vision, and programmatic decision-making executed within a Jupyter Notebook environment:


  • Board Initialization: An 8x12 grid is randomly populated with ships following standard game rules. Hidden ship coordinates are filled with sodium hydroxide (NaOH), while empty coordinates contain pure water. Both liquids remain visually identical prior to targeting.

  • Targeting & Execution: The Python Opentrons API directs the robot to dispense a purple cabbage juice indicator into the target well.

  • Detection & Vision Analysis: A camera mounted above the workspace captures an image of the plate. The script samples RGB values from the target well to identify color shifts caused by the pH reaction, outputting a hit or miss determination alongside an uncertainty score.

  • Algorithmic Decision Engine: The result feeds directly into a hunt-target heuristic algorithm. Hits trigger exploration of adjacent spaces (von Neumann neighborhood), while misses fall back to a checkerboard sweep pattern to maximize board coverage.

    05 — what's next? recovering ground truth from incorrect calls

    This system works great when we can assume all the calls are correct, but what if we can't? This is the question I ran into when I watched an early misclassification derailed the rest of the game, preventing the script from making good future calls. 

    Driven by this limitation, I started to explore symbolic logic solutions to improve error recovery. By modeling the governing rules of the game board as strict logical constraints, Z3 can continuously validate real-time optical observations against permitted board configurations. When a vision miscall triggers an impossibility, the solver detects the contradiction, isolates the erroneous data point, and prompts a re-sampling step to restore true ground state. This ongoing work aims to build closed-loop lab automation systems capable of self-correcting when exposed to imperfect physical sensors.
